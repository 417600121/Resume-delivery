## Context

当前应用是基于 Vue 3 和 Vite 的本地求职投递管理工具，主要界面集中在 `src/App.vue`、`src/styles.css` 和 `src/components/` 下的记录表格、个人信息面板及多个浮层组件。上一轮视觉刷新已经统一了部分颜色和间距，但仍然保留较强的卡片叠加、圆角和阴影表达，导致记录页更像信息卡片集合，而不是可长期使用的桌面工作台。

本设计承接 `proposal.md` 的视觉重置方向，并落实 `specs/modern-job-tracker-ui/spec.md` 的可观察行为。数据标准化、本地存储、导入导出、状态时间线和事件接口均视为不可变约束。

## Goals / Non-Goals

**Goals:**

- 用中性灰白画布、石墨文字、单一品牌强调色和少量语义色建立稳定的视觉层级。
- 将页面组织成“应用外壳、页面画布、记录工作面、少量浮层”，减少没有语义价值的卡片嵌套。
- 让桌面端投递记录页优先支持扫描、比较和跟进决策，并在受限桌面窗口中保持可操作。
- 让记录表格、个人信息分组、表单和浮层共享同一套边界、间距、焦点和反馈语言。
- 使用代表性数据量和桌面窗口尺寸完成视觉回归，且不引入新的运行时依赖。

**Non-Goals:**

- 不新增移动端适配或以移动端断点为目标的布局方案。
- 不修改记录数据结构、状态时间线语义、本地存储键、导入导出格式或业务事件接口。
- 不引入完整的第三方设计系统、字体服务、后端或路由层。
- 不复制 Linear、Atlassian 或 Apple 的品牌资产；只借鉴其关于克制、层级、令牌和一致性的通用原则。

## Decisions

### 1. 以小型 CSS 令牌系统作为唯一视觉基础

在 `src/styles.css` 中整理页面背景、工作面、浮层、正文、次要文字、分隔线、强调色、语义色、间距、圆角、阴影和焦点环等令牌。组件只消费这些令牌或少量局部变量，避免继续在文件末尾堆叠相互覆盖的主题规则。

选择令牌化方案，是因为当前页面由多个组件共享样式，统一修改需要可预测的传播路径。只调整局部颜色或继续追加覆盖规则会保留旧层级，使用完整外部设计系统则会增加依赖和迁移成本。

### 2. 采用“画布 + 工作面 + 浮层”的桌面布局

应用外壳继续使用左侧导航和主内容区，但主内容区改为稳定的桌面工作台：页面标题区负责上下文，轻量指标带负责摘要，记录表格或个人信息分组作为主要工作面，弹窗、菜单和提示只在需要时形成浮层深度。除真正需要隔离的浮层外，不再为每一段内容都添加圆角卡片和厚重阴影。

侧栏收起状态继续保留，并让主内容使用 `minmax(0, 1fr)` 等稳定约束；表格横向溢出只放在自身容器内，避免把页面整体推宽。

### 3. 记录工作面优先保证身份列和决策列

保留现有表格和事件接口，主要调整表头、列宽、行高、固定列、状态标签、下一步信息和操作列的视觉顺序。公司/职位是身份主列，状态、时间、下一步和链接是决策列，编辑、时间线、Markdown、外链和删除保持可发现但次要。

指标带改为轻量摘要，而不是五个同等重量的卡片；工具栏把搜索、筛选、排序和视图操作分组，空状态区分“没有记录”和“没有匹配结果”。

### 4. 浮层使用固定三段式结构

`RecordModal`、`HistoryModal`、`OptionsModal`、`MarkdownModal` 和 JSON 导出浮层统一采用标题区、可滚动内容区、操作区。内容区负责字段分组和错误反馈，操作区固定保存/取消等主要动作；关闭按钮、焦点环、遮罩和内部滚动边界使用同一套规则。

不引入新的弹窗库，原因是现有组件已经承担数据和事件逻辑，重做结构和共享 CSS 可以降低回归范围。

### 5. 个人信息按分组节奏表达层级

`PersonalInfoPanel` 保持现有分组、添加、选择、复制、编辑、排序和删除能力，把分组标题作为行级工作入口，把条目作为连续列表处理。空状态和添加区使用紧凑的背景与边界，不通过嵌套卡片制造额外层级。

### 6. 以状态矩阵和桌面截图作为验收依据

实现时按“零条、单条、多条记录”“有/无匹配结果”“空/有内容个人信息分组”“各类浮层”“展开/收起侧栏”建立验收矩阵，并在至少 1440×900、1280×800 和约 1024×768 的桌面窗口中检查重叠、溢出、焦点和操作可见性。这样可以把审美判断转成可复核的界面行为，而不是只依赖主观截图。

## Risks / Trade-offs

- [风险] 减少卡片和阴影后，部分区域的边界可能不够明显。→ 使用背景层级、分隔线、留白和局部强调线建立边界，并在空状态和弹窗中保留必要的浮层深度。
- [风险] 桌面受限窗口中的表格仍然较密集。→ 保证身份、状态、下一步和操作列的最小可读宽度，将横向滚动限制在记录工作面内，并避免页面级横向滚动。
- [风险] 共享 CSS 重构可能影响已有弹窗、拖拽或提示状态。→ 先整理令牌和基础控件，再按应用外壳、记录、浮层、个人信息的顺序逐区验证。
- [风险] 单一强调色可能削弱状态的即时区分。→ 状态同时使用文字、边框、图标或位置表达，并为成功、警告和危险保留足够对比度的语义色。
- [取舍] 不做移动端适配会限制窄屏浏览器的体验。→ 将范围明确限定为桌面端，优先保证用户实际使用的桌面窗口尺寸和长期扫描效率。

## Migration Plan

1. 先整理令牌和共享基础控件，不改变任何数据或事件代码。
2. 更新应用外壳、导航、页面标题、指标带和记录工作面，完成零条/单条/多条记录验收。
3. 更新记录表单、状态时间线、选项、Markdown 和 JSON 浮层，再验证键盘焦点及内部滚动。
4. 更新个人信息分组和条目状态，验证复制、编辑、拖拽排序和删除反馈。
5. 运行生产构建并完成桌面截图回归；如需回滚，只需撤销模板类名和样式改动，不需要数据迁移或存储回滚。
