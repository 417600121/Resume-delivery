## 上下文

本项目是一个基于 Vue 3 和 Vite 的本地求职投递管理工具，包含统一样式表、投递记录工作区、个人信息工作区和多个弹窗流程。数据保存在本地，项目已经使用 `lucide-vue-next` 提供图标。本次视觉改造必须继续使用现有前端技术栈，并保持现有数据契约和用户操作不变。

## 目标与非目标

**目标：**

- 为长期使用的个人工作工具建立克制、专业且统一的视觉系统。
- 让投递记录页成为明确的主要工作区，并提升状态和下一步操作的扫描效率。
- 让个人信息页和所有弹窗使用一致的层级、间距和交互语言。
- 保证宽屏桌面和受限桌面窗口尺寸下的布局稳定性。
- 明确视觉状态和键盘焦点行为，便于实施后验收。

**非目标：**

- 不修改本地存储结构、导入导出格式或记录标准化规则。
- 不涉及后端、身份认证、路由或服务端持久化。
- 不引入新的组件框架或视觉依赖。
- 不增加超出当前工作流所需的产品功能。

## 设计决策

### 1. 使用小型令牌化视觉系统

在 `src/styles.css` 中建立一组精简的 CSS 自定义属性，用于页面背景、表面、正文、次要文字、分隔线、强调色和状态色。整体采用温和的中性背景和中性表面，仅将珊瑚色用于主要操作和少量需要关注的状态。这样可以避免现有蓝色、珊瑚色、绿色、黄色和紫色同时争夺注意力。

备选方案：

- 只调整间距而保留当前配色：不采用，因为问题是整体对比度和层级混乱，而不只是间距问题。
- 引入完整的外部设计系统：不采用，因为本项目是本地单页工具，引入依赖会增加迁移和维护成本。

### 2. 由应用外壳负责建立页面层级

桌面端保留带文字标签的左侧导航栏。顶部区域只保留一个页面标题区和一组有明确优先级的操作；导入、导出和设置归入次要操作区，让“新增投递”成为最突出的主要操作。

应用外壳使用稳定的网格和弹性布局约束，确保主内容收缩时不会造成标题和操作区重叠。侧栏收起功能继续保留，但在较宽桌面窗口中默认展示展开状态。

### 3. 将投递记录区视为工作台，而不是卡片集合

页面使用轻量的统计信息带，下面接一个主要记录工作面。工具栏分离搜索和筛选；表格中以公司和职位作为身份主列，以紧凑的状态标记和清晰的下一步区域支持快速比较。桌面端继续使用表格作为对比界面；在受限桌面窗口中，必要的横向滚动限制在记录工作面内部，避免破坏整个页面布局。

空数据、单条记录和多条记录状态都需要单独设计，使数据量变化时页面仍然保持平衡。

### 4. 按用户意图组织表单

新增投递和状态时间线流程保留现有字段，但按身份信息、招聘上下文、下一步计划或时间线详情进行分组。分组标题、间距和底部操作区负责表达表单结构，不引入多步骤提交流程。

### 5. 使用克制的语义状态样式

状态、优先级、选中、删除操作和时间敏感的跟进事项分别使用明确的语义表现。颜色只用于辅助，不替代文字标签。选中和 `focus-visible` 状态使用轮廓或内嵌强调线，即使没有悬停也能被识别。

### 6. 使用代表性视觉状态进行验收

实施验收覆盖零条、单条和多条投递记录；空的和有内容的个人信息分组；投递、状态时间线、选项和 Markdown 弹窗；以及宽屏和受限桌面窗口。构建验证使用现有 Vite 构建命令，并通过浏览器截图检查溢出、重叠和空状态平衡。

## 风险与取舍

- [风险] 更强的视觉层级可能让次要操作不够显眼。→ 通过带文字的次要控件和工具提示保留可发现性，并验证键盘可达性。
- [风险] 受限桌面窗口中的密集表格可能降低扫描效率。→ 将溢出限制在记录工作面内，并优先保证身份、状态、下一步和操作列的可读性。
- [风险] 修改共享 CSS 可能意外影响弹窗或拖拽状态。→ 先更新令牌和共享基础样式，再逐一验证弹窗与个人信息交互状态。
- [风险] 克制的配色可能减少状态的即时色彩提示。→ 保留文字标签，并使用高对比度语义色、边框和结构线索共同表达状态。

## 迁移计划

1. 增加视觉令牌和共享基础样式，不修改数据逻辑。
2. 更新应用外壳和投递记录工作区，验证空状态和有数据状态。
3. 更新弹窗和个人信息布局，验证焦点和受限桌面窗口状态。
4. 在代表性的桌面窗口尺寸下运行构建和视觉检查。
5. 回滚只需撤销界面展示层改动，不需要数据迁移或存储回滚。
